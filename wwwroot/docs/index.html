Démarrage

TaskFlow nécessite un compte pour accéder à vos tâches : chaque utilisateur ne voit que les tâches qu'il a créées.

Créer un compte

Cliquez sur S'inscrire en haut de la page, renseignez votre email et un mot de passe (8 caractères minimum, avec au moins un chiffre). Aucune confirmation par email n'est requise : vous êtes connecté immédiatement après inscription.

Se connecter / se déconnecter

Utilisez Se connecter avec l'email et le mot de passe choisis à l'inscription. Le lien Se déconnecter apparaît en haut à droite une fois connecté.

Dashboard

La page d'accueil affiche un tableau de bord résumant l'état de vos tâches :

  • Total — nombre total de tâches que vous avez créées.
  • Terminées — tâches cochées comme terminées.
  • En cours — tâches non terminées dont l'échéance n'est pas dépassée.
  • En retard — tâches non terminées dont l'échéance est dépassée.
  • Pourcentage complété — calculé automatiquement (terminées / total).

Le dashboard affiche aussi vos 5 tâches les plus urgentes (non terminées, triées par priorité décroissante puis par date d'échéance).

Gérer ses tâches

Créer une tâche

Depuis la liste des tâches, cliquez sur Créer. Champs disponibles :

  • Titre (obligatoire, 200 caractères max)
  • Description (optionnelle, 1000 caractères max)
  • Priorité — Basse, Moyenne ou Haute (Moyenne par défaut)
  • Date d'échéance (obligatoire, 7 jours après aujourd'hui par défaut)
  • Catégorie (optionnelle)
  • Heures estimées (optionnelle, entre 0 et 1000)
  • Assigné à (optionnel, voir la section « Assigner une tâche »)
Modifier ou marquer terminée

Ouvrez une tâche et cliquez sur Modifier pour changer n'importe quel champ. Depuis la liste, une case à cocher permet de basculer rapidement le statut terminé/non terminé sans ouvrir le formulaire complet.

Supprimer une tâche

Une page de confirmation s'affiche avant toute suppression définitive — vos commentaires et pièces jointes associés sont supprimés avec la tâche.

Filtrer et rechercher

La liste des tâches propose plusieurs filtres combinables :

  • Statut — en cours, terminées, ou priorité haute uniquement.
  • Recherche texte — filtre les tâches dont le titre contient le texte saisi.
  • Catégorie — n'affiche que les tâches de la catégorie choisie.

Les tâches non terminées sont toujours affichées avant les tâches terminées, puis triées par date d'échéance. La liste est paginée par blocs de 10 tâches.

Catégories

Les catégories permettent de regrouper vos tâches (ex. Travail, Perso, Urgent, Entraînement — ces 4 catégories existent par défaut). Chaque catégorie a un nom et une couleur, modifiables ou supprimables à tout moment depuis Catégories dans le menu.

Attention : si des tâches sont encore liées à une catégorie au moment de sa suppression, l'opération peut échouer — retirez ou réassignez d'abord la catégorie de ces tâches.

Assigner une tâche

Lors de la création ou de la modification d'une tâche, vous pouvez sélectionner un autre utilisateur dans le champ Assigné à. Son email s'affiche alors sur la tâche.

Important : l'assignation est aujourd'hui purement informative. La tâche reste visible uniquement dans votre liste de tâches, pas dans celle de la personne assignée — elle sert à indiquer qui est responsable, pas à partager l'accès à la tâche.

Commentaires

Sur la page de détail d'une tâche, ajoutez un commentaire (1000 caractères max) via le formulaire en bas de page. Les commentaires sont affichés du plus récent au plus ancien, avec le nom de leur auteur. Vous ne pouvez supprimer que vos propres commentaires.

Pièces jointes

Depuis la page de détail d'une tâche, vous pouvez joindre un fichier :

  • Taille maximale : 10 Mo par fichier.
  • Types autorisés : PDF, Word (.doc/.docx), Excel (.xls/.xlsx), images (.png/.jpg/.jpeg), texte (.txt).

Cliquez sur le nom d'un fichier pour le télécharger. Seul l'utilisateur propriétaire de la tâche peut voir, télécharger ou supprimer ses pièces jointes.

FAQ / erreurs courantes

Pourquoi je ne vois pas une tâche qui m'a été assignée ?

C'est le comportement actuel de l'application : l'assignation est une simple étiquette, elle ne rend pas la tâche visible dans votre propre liste. Seul le créateur de la tâche la voit apparaître dans « Mes tâches ».

« Type de fichier non autorisé » lors d'un envoi de pièce jointe

Seules certaines extensions sont acceptées (voir la section « Pièces jointes »). Convertissez le fichier dans un format supporté avant de le joindre.

« Le fichier est trop volumineux » lors d'un envoi de pièce jointe

La taille maximale par fichier est de 10 Mo. Compressez le fichier ou réduisez sa taille avant de le joindre à nouveau.

Stack et architecture

TaskFlow est une application ASP.NET Core MVC (.NET, cible net10.0), avec authentification ASP.NET Identity et base SQLite (taskflow.db).

Dans Program.cs, le pipeline de démarrage enregistre AddDbContext<AppDbContext> (SQLite), AddDefaultIdentity<IdentityUser> + AddRoles<IdentityRole> + AddEntityFrameworkStores<AppDbContext>. L'ordre UseAuthentication() avant UseAuthorization() est important : inversé, la connexion ne fonctionne plus.

app.UseAuthentication();
app.UseAuthorization();

app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");

app.MapRazorPages(); // pages Identity (login/register)

Modèle de données

AppDbContext hérite de IdentityDbContext<IdentityUser> : les tables Identity (AspNetUsers, etc.) cohabitent avec les tables métier.

  • TodoTask — entité centrale. CategoryId (nullable) vers Category, UserId (propriétaire), AssignedToUserId/AssignedToUserName (assignation informative, nom dénormalisé), collections Comments et Attachments, enum Priorite (Basse/Moyenne/Haute).
  • Category — Name, Color, collection Tasks.
  • Comment — Content, TaskId (obligatoire), UserId/UserName dénormalisés pour éviter une jointure AspNetUsers à l'affichage.
  • Attachment — OriginalName (nom affiché) distinct de StoredName (nom généré par GUID sur disque), TaskId, UserId.
  • Tag — existe comme modèle et DbSet<Tag>, mais n'est pas encore relié à TodoTask (pas de table de jointure).

OnModelCreating seed des Category et TodoTask initiales via HasData — ces seeds ne doivent être modifiés que par une nouvelle migration, jamais en éditant une migration déjà appliquée.

Cycle de vie d'une requête

Le routing par convention ({controller=Home}/{action=Index}/{id?}) fait correspondre une URL à une méthode de contrôleur : par exemple GET /Todo/Edit/5 appelle TodoController.Edit(int id).

Chaque contrôleur suit le pattern PRG (Post-Redirect-Get) : après un POST réussi, on redirige toujours vers une action GET (généralement Index) plutôt que de renvoyer une vue directement, pour éviter la double soumission au rafraîchissement de page.

await _context.SaveChangesAsync();
TempData["Succes"] = "Tâche créée avec succès.";
return RedirectToAction(nameof(Index));

Sécurité par propriétaire

Tous les contrôleurs métier sont [Authorize]. Au-delà de ça, chaque accès à une entité filtre systématiquement par UserId pour empêcher un utilisateur d'accéder aux données d'un autre en modifiant l'Id dans l'URL :

var userId = _userManager.GetUserId(User);

var task = await _context.TodoTasks
    .FirstOrDefaultAsync(t => t.Id == id && t.UserId == userId);

if (task == null)
    return NotFound(); // 404, pas 403 : on ne révèle pas que la tâche existe

Ce pattern doit être respecté pour toute nouvelle action touchant une entité liée à un utilisateur (voir TodoController, CommentController, AttachmentController).

Upload de fichiers

AttachmentController.Upload impose une taille maximale de 10 Mo et une whitelist d'extensions (.pdf, .doc, .docx, .xls, .xlsx, .png, .jpg, .jpeg, .txt). Le fichier est stocké sur disque dans wwwroot/uploads sous un nom généré par GUID (StoredName), distinct du nom original (OriginalName) affiché à l'utilisateur — cela évite les collisions de noms entre utilisateurs.

var storedName = $"{Guid.NewGuid()}{extension}";
var filePath = Path.Combine(_env.WebRootPath, "uploads", storedName);

Pagination

Helpers/PaginatedList<T>.CreateAsync(IQueryable<T> source, int pageIndex, int pageSize) exécute lui-même le Skip/Take et compte le total en une seule requête paginée. Ne jamais appeler .ToListAsync() sur la requête avant de la lui passer, sinon la pagination charge toutes les lignes en mémoire avant de paginer.

var paginatedTasks = await PaginatedList<TodoTask>.CreateAsync(
    query.OrderBy(t => t.EstTerminee).ThenBy(t => t.DateEcheance),
    pageNumber,
    pageSize: 10
);

Commandes de développement

dotnet build                     # Compiler le projet
dotnet run                       # Lancer l'application
dotnet watch run                 # Lancer avec hot-reload

dotnet ef migrations add <Nom>   # Créer une migration après modif d'un modèle
dotnet ef database update        # Appliquer les migrations à taskflow.db

Il n'y a pas de suite de tests automatisés dans ce dépôt actuellement.

Points d'attention connus

  • Tag non relié — le modèle Tag existe et possède un DbSet, mais aucune relation n'existe encore avec TodoTask.
  • Suppression de catégorie — CategoryController.DeleteConfirmed ne vérifie pas si des tâches sont encore liées avant de supprimer ; le DELETE peut échouer si une contrainte de clé étrangère stricte existe en base.
  • Assignation de tâche — AssignedToUserId n'affecte pas la visibilité de la tâche : elle reste filtrée par UserId propriétaire dans toutes les requêtes (Index, Dashboard), pas par assignation.
